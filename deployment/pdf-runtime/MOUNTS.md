# Operator fonts and extensions

Unreleased source also discovers [value-pipe extension JARs](../../nuaforma-template/README.md#extensible-value-pipes-unreleased-source) from the existing extension mount. Package the service entry and matching static pipe descriptor with the implementation and non-conflicting dependencies. The server's existing startup loader snapshots/validates JARs before provider construction; DOCX/PDF providers capture their value registry under that loader and reuse it after the startup thread context is restored. The loader and private copies remain alive until service shutdown, then close/clean up. Restart to add/change/remove pipes; templates/REST cannot supply an extension JAR or choose a class loader. Existing class-version/origin/conflict/manifest checks and renderer/validator mount isolation remain unchanged. Published alpha images do not yet contain these APIs; use a source build for this feature.

The service accepts read-only mounts at `/opt/nuaforma/custom-fonts` and `/opt/nuaforma/extensions`. Compose includes both; set host sources through `NUAFORMA_CUSTOM_FONTS_DIR` and `NUAFORMA_EXTENSIONS_DIR`, defaulting to adjacent `custom-fonts`/`extensions` directories. Compose creates absent empty host directories. These paths are ignored by Git and excluded from the image build context. Explicit Docker runs use `--mount type=bind,source=<absolute-host-directory>,target=/opt/nuaforma/custom-fonts,readonly` and the equivalent extension target, with every service isolation flag retained.

UID/GID 1000 must be able to traverse directories and read files. Use appropriate host ACLs/group permissions, not root or a relaxed sandbox. Empty/absent paths mean no installed resources. Invalid extension packages fail clearly; individual font failures follow the source policy below. Trusted target overrides are container variables `NUAFORMA_FONT_DIRECTORY`/`NUAFORMA_EXTENSION_DIRECTORY`, or JVM properties `nuaforma.fonts.directory`/`nuaforma.extensions.directory`; keep mount targets consistent. These are never REST options.

## Fonts

Unreleased issue #100 source adds opt-in DOCX `fontMode: "embed", fontSelection: "used"`. Used supported faces resolve against explicit request declarations, then MOUNT, then IMAGE, without a fixed family list. Existing embedded faces remain intact; unused catalog fonts are not embedded. Default preservation and existing declared selection retain their behavior. See the [automatic profile and restrictions](../../nuaforma-docx/README.md#automatic-embedding-unreleased-issue-100-source).

The source service/Playground launcher explicitly configures IMAGE roots through `NUAFORMA_BUNDLED_FONT_DIRECTORIES` / `nuaforma.fonts.bundledDirectories`. Defaults are `/opt/nuaforma/renderer/usr/share/fonts` and `/opt/nuaforma/renderer/opt/libreoffice26.8/share/fonts/truetype`, separated by the platform path separator (`:` in the container). Font bytes are snapshotted at startup without launching the converter or consulting host fontconfig. Restart to reload. These are trusted paths, never generation options. Embedded applications can use `DeploymentFonts.load(List<Path> bundledDirectories, Path mountedDirectory)` or the JVM properties; no IMAGE roots are inferred outside the launcher.

At most eight IMAGE roots are accepted, each scanned to depth eight, with at most 1024 entries, 256 recognized files, 16 MiB per file and 64 MiB scanned bytes per root. IMAGE uses the same independently validated SFNT metadata profile as MOUNT. The combined catalog permits at most 256 distinct byte snapshots and 128 MiB of scanned bytes, including rejected/duplicate reads across roots. Recursive traversal does not follow symbolic links. Same-tier ambiguous identities are unusable for automatic selection. Catalog origin `bundled` represents IMAGE. Request font limits remain unchanged; PDF fallback still stages only required mounted families.

Use standalone TTF/OTF files in a flat directory. TTC/WOFF/WOFF2 are recognized but rejected by the current SFNT profile; ordinary notice files are not fonts. Startup permits at most 256 directory entries, 64 recognized font files, 16 MiB per font and 64 MiB total, then retains an immutable byte/metadata snapshot. Families come from Unicode font metadata, not filenames.

Unreleased issue #99 source validates each file independently. Unreadable, malformed, unsupported, oversized or non-regular files (including symlinks) are excluded completely, while independently valid fonts and providers remain available. Identical byte copies are deduplicated. Different bytes claiming any common case-insensitive family/face exclude every involved file, including its other aliases and identical copies; diagnostics identify each rejected basename and a conflicting basename. No filename order chooses a winner. An all-rejected mount gives an available empty catalog; it does not disable document providers. Published `0.2.0-alpha.1` artifacts retain all-or-nothing loading.

Relative paths, symlink/non-directory mount roots, directory enumeration/access failures, entry/file-count overruns and the aggregate byte budget still fail snapshot construction. Rejected/conflicting/duplicate files count toward scan limits; all bytes actually read count toward the aggregate budget, including reads that later fail validation. Oversized files are read only up to 16 MiB plus one detection byte. No fatal JVM error is recovered. Fix operator configuration and restart; do not relax limits or isolation to make the mount load.

At provider activation, production emits `MOUNTED_FONT_REJECTED` with an escaped basename and safe loading-failure result. Development adds an application-owned reason, exception/cause types and bounded class/method/line stacks, without exception messages or full paths. See [logging bounds](../../docs/logging.md). Embedded callers can invoke `DeploymentFonts.reportFailures(logging)` explicitly, or supply logging through a context-aware provider operation; reporting occurs once per snapshot when an enabled scope is first available.

`/api/v1/capabilities` lists fonts per provider with family, face, source and logical resource selector. Mounted IDs are `nf-mounted-<sha256>`; bundled renderer entries have null resources. Copy the exact selector from capabilities into existing font declarations for DOCX validate/embed without an upload. DOCX preserve is unchanged. PDF can automatically stage mounted fonts needed by the template. Explicit private resources and template-embedded families precede mounted fallback, then bundled fonts. Only required mounted families and their available faces reach that request's private font directory; combined staged standalone-font bytes remain capped at 64 MiB. Private uploads never change catalogs or become visible to other requests.

Technical embedding flags remain enforced without rewriting them or requiring ownership declarations. Availability is not permission to embed, a glyph-coverage guarantee or proof of every variable-font axis. Callers/operators remain responsible for usage rights. Mounting a font does not authorize redistributing it in an image. NuaForma does not globally install customer fonts or expose the entire mount to LibreOffice.

## Extensions

Installed extensions are arbitrary operator-trusted executable JVM code with full application-process permissions. They may perform whatever compatible functionality their author chooses. There is no functionality allowlist, approval process or extension-specific sandbox. Do not install untrusted code. Document-rendering isolation does not protect the application against installed extensions, and generation requests cannot install code.

Compile against Java 17 and the public contracts for broad embedded compatibility. The source server now runs Java 25 and can also load explicitly server-only Java 25 extensions; those binaries are not Java-17-compatible embedded providers. Published containers through alpha.3 still require Java-17-compatible extensions. Startup uses the running JVM's effective multi-release view and rejects newer/preview class versions before provider initialization. Use standard ServiceLoader registration and its matching static descriptor from the contracts/core guides. Supply non-conflicting dependencies alongside the provider JAR, or shade/relocate them; do not bundle duplicate NuaForma, Kotlin or application classes. Those third-party dependencies and extension behavior remain the operator's responsibility, not automatically reviewed NuaForma components.

Startup permits at most 256 directory entries and snapshots at most 256 MiB of JARs into private ephemeral `nf-extensions-*` storage. Budget this in addition to request storage in the tmpfs. Reject malformed archives, over 100000 entries per JAR, unsafe archive names, duplicate effective runtime classes and application-class conflicts. Multi-release JARs use the running JVM's effective view (Java 25 for current source; Java 17 in published alpha.3). Reject manifest `Class-Path` indirection; put dependencies explicitly in the mount, not URLs or hidden paths. No dependencies are downloaded automatically.

Current source checks raw entry names before any parent-classpath lookup for that JAR, including entries hidden by multi-release selection. Use canonical relative `/`-separated names; absolute paths, backslashes, drive/URI colons, NUL, empty segments and `.`/`..` segments fail with `INVALID_EXTENSION_ARCHIVE`, rather than being normalized into accepted paths. Directory trailing slashes, ordinary resources, Unicode and inner-class names remain supported. Inspection reads archive entries without extracting them to entry-controlled filesystem paths or initializing classes. Failure cleans up the private startup copies. Production and Playground share this boundary; existing published images remain unchanged.

The parent-first classloader uses only snapshotted JARs plus existing application dependencies. Descriptor-origin and contract compatibility checks precede initialization. Missing dependencies, invalid/incompatible metadata and provider-ID conflicts produce discovery diagnostics, never a classpath-order fallback. Legacy providers need not implement the optional font-catalog facet; enumeration reports `UNSUPPORTED`. Published contract `0.2` accepts legacy `0.1` providers. Unreleased source contract `0.4` additionally accepts `0.2`/`0.3` minima; DOCX requires `0.3` for structured diagnostics and PDF requires `0.4` for optional operator conformance metadata. Existing providers gain no mandatory facet; artifact release versions and contract minima remain distinct.

## Restart and isolation

Both mounts are startup snapshots. Restart to apply host changes; there is no hot reload. Keep inputs stable during copying/scanning: partially updated fonts may be excluded until the next restart, and malformed extension updates fail startup. The font snapshot stays private to provider instances, while staged resources stay request-private. The extension snapshot is outside the renderer/validator root and is closed/cleaned during normal shutdown. Forced termination relies on ephemeral storage destruction.

Never add mounts, startup snapshots, application files or sibling requests to Bubblewrap. The renderer sees only its reviewed immutable root and current request resources. Operator JARs never enter the validator child's classpath. Preserve non-root/read-only execution, init, no-new-privileges, quotas and reviewed filters. Public image distribution still requires the exact candidate's completed license/source-provision audit and explicit publication authorization.

## Qualification

Run the complete split Java 17/25 build and the service qualification in [SERVICE.md](SERVICE.md). The server tests compile independent provider JARs against only contracts/Kotlin and verify startup snapshots, metadata rejection before initialization, dependency/ID/class conflicts and the Java-17 multi-release view. DOCX tests verify mounted snapshots, private overrides, malformed/conflicting fonts and limits.

For real mounted-resource checks, build synthetic providers with `:nuaforma-server:prepareEngineQualification` and `dev.nuaforma.server.MountedProviderFixture <output-directory> [required-minor] [missing-dependency]`. Run `tools/container/qualify_mounts.py` with the exact local image, `--fonts` pointing to generated QA font copies, `--extensions` to the generated compatible provider, `--fixtures nuaforma-docx/build`, and a fresh `--output` directory. This check deliberately changes and restores those QA copies after startup; never point it at an operator's production files. Run `qualify_mount_failures.py` with generated incompatible/missing-dependency providers and a fresh output directory. Private interoperability fonts are not tracked, bundled or published.

Independently inspect generated DOCX font embedding and PDF font streams, render every representative page and decode margin barcodes. `tools/container/verify_mount_outputs.py` verifies exact deobfuscated DOCX font bytes and 300-DPI barcode scans from the mounted, private, snapshotted and template-embedded cases. Compare the unchanged DOCX/PDF geometry with the approved reference; retain the scoped issue #32 limitation rather than introducing a new tolerance. Run the native sandbox probe with both mounts present outside the sandbox. These checks supplement, not replace, the final license/source-distribution gate.
