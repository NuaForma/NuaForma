# NuaForma 0.4.0-alpha.2

This evaluation alpha makes unsupported Word content easier to diagnose and provides an explicit Playground tool for preparing a supported template copy.

- Development responses and logs identify the concrete rejected DOCX package part when its name can safely be shown. Production retains its restricted diagnostics.
- **Clean template and download report** removes unsupported parts, objects and formatting from a separate DOCX copy. Its ZIP contains `cleaned-template.docx` and `cleanup-report.txt`, with each removal/restoration, part, available XML location and reason. The report can support an issue describing missing functionality.
- Remaining variables, pipes, conditions, repetitions and malformed markers stay literal. No JSON data or font/resource uploads are used by cleanup. Open the copied template in Word and decide whether its contents and appearance are acceptable before replacing the original.
- Normal generation remains strict; unresolved/unsafe packages, cancellation and exceeded limits do not produce a falsely qualified cleaned artifact. The tool is exclusive to the development Playground composition.
- Contract 0.9 adds the optional cleanup facet. Compatible older providers remain accepted; the new PDF provider requires 0.9. Keep the six NuaForma libraries aligned.

See the [cleanup guide](https://github.com/NuaForma/NuaForma/blob/v0.4.0-alpha.2/docs/template-cleanup.md). Required fonts and normal syntax/data checks still apply when generating PDF from the cleaned template. Existing Word formatting, PDF profiles and embedding policies remain unchanged.

Java 17/25, independent consumers, native AMD64/ARM64 and the actual Sonar Quality Gate pass on the qualified source. The full local suite has 1,129 passing JVM tests, and all 16 existing Playground JavaScript tests pass. New-code coverage is 80.8%, with no new issues or duplication. A cleaned public logo-letter fixture retains identical PDF text and rendered page pixels. Private documents and existing golden files remain untouched.

## Downloads and evaluation scope

The six alpha libraries use [Nexus prereleases](https://repo.nuaforma.dev/repository/nuaforma-prereleases/); stable versions use Maven Central. Both production and development Playground images provide native AMD64 and ARM64. Prereleases leave `latest` unchanged. No LibreOffice, Word or cloud service is required at runtime; ODT remains future work.

Runtime inputs retain official Temurin 17.0.21+9 validators, Temurin 25.0.5+8 service/Playground and pinned 2026-10-30 Debian packages. Unchanged third-party sources/notices remain at [sources-v0.3.0-alpha.5](https://github.com/NuaForma/NuaForma/releases/tag/sources-v0.3.0-alpha.5); the signed v0.4.0-alpha.2 tag supplies NuaForma source. Preparation checks those public identities without downloading the source archives again.

Residual runtime findings remain open under [#51](https://github.com/NuaForma/NuaForma/issues/51). The single protected final review must accept them for **0.4.0-alpha.2 only**; earlier approvals do not transfer. See the [candidate audit](https://github.com/NuaForma/NuaForma/blob/v0.4.0-alpha.2/docs/release-0.4.0-alpha.2-audit.md). This evaluation release makes no general production-safety or zero-vulnerability claim.
