# NuaForma 0.5.0-alpha.3

This evaluation alpha exposes the concrete native PDF render failure in the development Playground and correlated logs.

- After `NATIVE_PDF_RENDER_STARTED`, the existing Cause line identifies the native failure code and recognized built-in explanation. Examples are `CONTENT_OVERFLOW: Paragraph indentation exceeds the physical page` and `MISSING_GLYPH: The supplied font cannot encode requested text`.
- The same detail appears in development `DOCUMENT_SOURCE_DETAIL` logs beside the ordinary `GENERATION_REJECTED` event, correlated by request ID. Standard PDF and PDF/A-3b failures are covered.
- Only fixed application-owned explanations are admitted. Unknown/custom exception text keeps its failure code with a fixed fallback. Arbitrary messages, paths, credentials and stacks are omitted; production remains restricted.
- Unavailable DOCX coordinates and font identities are not invented. A missing glyph in an available face is distinct from a missing family/variant. Passing cleanup or reaching the render event does not prove that output can be produced.

The change was delivered through [PR #305](https://github.com/NuaForma/NuaForma/pull/305). Nineteen focused JVM tests and twenty Playground JavaScript tests passed. Actual standalone production/Playground HTTP probes checked eight rejected renders with correlated development-only causes and four successful, independently validated standard/PDF-A-3b controls. Full Java 17/25 and native AMD64/ARM64 qualification passed, including actual SonarCloud analysis with 99.6% new coverage and zero new duplication. No public API, dependencies, golden files, supported layout profile or rendering behavior changed.

All six libraries publish to [Nexus prereleases](https://repo.nuaforma.dev/repository/nuaforma-prereleases/); production and development-only Playground images retain native AMD64/ARM64. Java 17 libraries/validators and Java 25 applications keep their existing boundaries. Standard PDF and PDF/A-1b/2b/3b retain embedding and independent validation; PDF/A-1b rejects requested watermarks. Prereleases leave `latest` unchanged and do not publish to Maven Central. See the [diagnostic guide](https://github.com/NuaForma/NuaForma/blob/v0.5.0-alpha.3/docs/template-diagnostic-pdf.md).

Runtime pins and corresponding-source baseline remain unchanged: Temurin 17.0.21+9 validators, Temurin 25.0.5+8 applications, authenticated Debian snapshot 20261030T000000Z and [sources-v0.3.0-alpha.5](https://github.com/NuaForma/NuaForma/releases/tag/sources-v0.3.0-alpha.5).
