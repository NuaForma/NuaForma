# NuaForma 0.3.0-alpha.4

Find a template syntax error without sharing the document. In the development Playground, **Download diagnostic PDF** creates a literal copy of the original failed template, marks the first locatable parser error with a red ERROR 1 label and appends an explanation containing the reason, parser excerpt, part, paragraph and position. Generation remains unsuccessful; correct the original template and try again to find the next error. Reporting one error avoids misleading cascading failures.

The separate `/api/v1/diagnostics/template` multipart operation exists only in trusted development mode. Production returns 404 and request data cannot enable it. The Playground resends the original failed upload, preserves the original error when rendering is unavailable and offers a separately validated standard PDF. Unsupported source structures/fonts can prevent rendering; no text-only PDF or Office fallback conceals that failure. Byte/work limits, admission, cancellation, private cleanup and structural validation remain enabled.

Contract 0.6 adds optional `TemplateDiagnosticProvider` while retaining existing constructors/interfaces and compatible older provider minima. New DOCX/PDF providers declare minimum 0.6 so older runtimes reject them before initialization. Java 17 remains the library/validator baseline; Java 25 runs the service and Playground. No production dependency, extra module or checkbox pipe is introduced. Mixed expression quotes, detailed development diagnostics, passive template references and the qualified native PDF profile are retained.
