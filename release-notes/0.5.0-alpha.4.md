# NuaForma 0.5.0-alpha.4

This evaluation alpha improves DOCX layout and exact font identity through the shared native PDF engine.

- Ordinary soft line breaks retain their source styles, empty lines and paragraph-mark formatting in body text, qualified table cells and page bands. Unsupported page/column/clear controls remain explicit rejections.
- Exact line spacing measures actual glyph ink after physical placement. Valid overlapping lines are retained; true physical top/bottom overflow keeps measured rejection and atomic output.
- Top-level fixed body tables keep their declared grid when they extend into the margin within the physical page. Qualified oversized unshaped words wrap at grapheme boundaries without narrowing columns or inserting hyphens. Nested, automatic-width and page-band restrictions remain explicit.
- Deployment/DOCX and PDF use one bounded OpenType naming helper. Extended designs such as Aptos Display retain their precise family and cannot impersonate Aptos. Ordinary regular/bold/italic/bold-italic linking remains supported; missing faces and embedding restrictions still fail clearly.

## Compatibility and verification

The additive shared model introduces `PdfLineBreak`, `PdfParagraph.paragraphMarkStyle` / `withParagraphMarkStyle(style)` and opt-in `breakLongWords` / `withLongWordBreaking(enabled)`. Existing JVM constructors and copy entry points remain. **Exhaustive Kotlin handling of `PdfInline` must include the new `PdfLineBreak` variant.** `OpenTypeFontNames.families(nameTable: ByteArray): Set<String>` is Java-callable and returns an immutable set from a raw naming table. No module or dependency is added.

[PR #309](https://github.com/NuaForma/NuaForma/pull/309) passed full Java 17/25 and native AMD64/ARM64 qualification and actual SonarCloud analysis on signed source `b90c1f9b66650144acd04036038b1229c98bc3e0`. The local normal build passes 1,862 JVM tests. Synthetic exact-source Word controls and new initial golden images cover the layout changes; existing goldens are unchanged. Real server/Playground standard PDF and PDF/A-1b/2b/3b, cleanup/reuse and genuine physical-bound negatives are qualified. Production diagnostics remain restricted; the container checks bind rejected requests to actual safe logs.

The local corpus converts 14 of 250 unchanged documents. Eleven unaffected PDFs (18 pages) remain pixel-identical. Three corrected Aptos documents (six pages) agree with independent Word exports in page counts and position-sorted text and were visually reviewed. These are bounded compatibility results, not arbitrary DOCX or pixel-perfect fidelity guarantees. Private corpus files and fonts are not distributed.

Six libraries publish to Nexus prereleases, with native AMD64/ARM64 production and development-only Playground images. Standard PDF and PDF/A-1b/2b/3b retain embedded fonts and independent validation; PDF/A-1b continues to reject requested watermarks. Java 17 embedded libraries/validators and Java 25 applications remain unchanged. Prereleases leave Maven Central and `latest` unchanged. ODT remains future work.

Official current Java patches were rechecked on 2026-11-15: Temurin 17.0.21+9 validators and 25.0.5+8 applications.
