# NuaForma 0.5.0-alpha.1

This evaluation alpha adds Boolean checkbox content and substantially broadens the qualified native Word-to-PDF profile. It keeps the six-library structure and requires no LibreOffice, Word or cloud conversion service at runtime.

- Insert boxed or bare checks/crosses with `{accepted | checkbox()}` or `{accepted ?? false | checkbox(false, "check", "cross")}`. Expressions evaluate first; vectors follow surrounding size and bold styling without requiring a checkbox-symbol font. See the [checkbox profile](https://github.com/NuaForma/NuaForma/blob/v0.5.0-alpha.1/docs/checkbox-content.md).
- Retain more bounded Word authoring/package metadata, JPEG pictures, property/form/sequence fields, bookmark boundaries and note metadata. Sequence names use Word's qualified case-insensitive identity. Valid owned source-font resources remain passive and do not supply missing deployment fonts.
- Improve supplied-font selection, private-use glyphs, synthetic bold, natural/minimum line metrics, justification, character spacing, trailing-space underlining and implicit paragraph-style defaults.
- Extend shared table layout with preferred physical/percentage widths and automatic fitting, minimum row heights, effective cell margins, qualified indentation/right-margin overflow and legal first-row fragmentation. Ordinary unmerged body-cell keep-lines/widow defaults follow the qualified Word interpretation; unsupported combinations still fail explicitly.
- Admit up to 256 native DOCX package members while retaining existing byte limits and stricter caller limits. Playground cleanup retains supported template bytes and never evaluates template instructions.

Contract 0.10 adds bounded vector content; the neutral PDF model adds the approved immutable typography, paragraph and table options. Existing Java constructors are retained. These are alpha APIs: exhaustive handling of expanded variants/enums may require consumer updates. Java 17 remains the library baseline; server/Playground use Java 25.

The normal local build passed 1,781 JVM tests, including 852 DOCX/PDF tests. Required Java 17/25, native AMD64/ARM64 and actual Sonar qualification passed on the feature source. Synthetic exact-source Word exports cover A4/Letter and representative standard PDF/PDF-A-1b/2b/3b cases. The latest group independently checked 34 real-HTTP PDFs / 52 exact native golden pages, six Playground cleanup/reuse cases / eight exact golden pages, and sixteen explicit negative HTTP cases without PDF output.

Private corpus progress is eleven conversions from 250 unchanged documents, with all fifteen previously successful pages pixel-identical. This is bounded compatibility evidence, not general Word fidelity. The newly converted document retains a trailing blank page and has no actual Word-export comparison. Other unsupported formatting, missing fonts and physical overflow remain explicit limitations. Existing golden replacement was limited to the two specifically approved mixed-Latin references; private documents/fonts are not distributed.
