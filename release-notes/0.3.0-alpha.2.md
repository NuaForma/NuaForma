# NuaForma 0.3.0-alpha.2

This evaluation alpha accepts DOCX documents with a passive attached Word template, including local, UNC and HTTPS references, without opening or downloading that template. Saved document styles and content remain authoritative; generated DOCX is detached from the external template. Automatic template style updates still reject explicitly. This fixes #139.

The native PDF engine, Java 17 libraries, Java 25 service/Playground and bounded independent PDF validation retain the qualified profile from alpha.1. Standard PDF and PDF/A-1b, 2b and 3b remain supported; requested watermarks work in standard PDF, 2b and 3b, while 1b explicitly rejects them. Unsupported document constructs continue to reject; this is not universal Word compatibility.

- Maven Central: six `dev.nuaforma` libraries at `0.3.0-alpha.2`.
- Production: `ghcr.io/nuaforma/nuaforma:0.3.0-alpha.2`.
- Development Playground: `ghcr.io/nuaforma/nuaforma-playground:0.3.0-alpha.2`.
- Both container indexes include native Linux AMD64 and ARM64. Prereleases do not move `latest`.
- Website and matching download kits: https://nuaforma.dev/.

Release preparation reuses existing green CI instead of repeating full per-container qualification. The final protected approval covers the exact signed Maven bundle, four image archives, publication and website. Candidate/receipt assets identify the signed source, CI, archive/config hashes and published index digests.

Exact third-party package, both-JVM and dependency inventories are checked against the alpha.1 source review. Matching corresponding-source archives remain publicly available with their original hashes at [v0.3.0-alpha.1](https://github.com/NuaForma/NuaForma/releases/tag/v0.3.0-alpha.1); generated in-image notices point there. NuaForma application sources are provided by this signed release tag. Original third-party notices and legal trees remain in the images.

The final approval explicitly reviews the retained Java 17.0.20.1+1 / 25.0.4.1+1 patch exception and open runtime/font/XML findings tracked in #51 for this evaluation alpha only. Remediation remains assigned to 0.4.0. Review these limitations before deployment; no zero-vulnerability claim is made.
