# NuaForma 0.3.0-alpha.3

This evaluation alpha makes Word-authored expressions less sensitive to quotation style. Straight double/single and typographic quotes can be mixed, including different opening and closing forms. Ordinary document text and inserted values remain literal. Interior quotes at an ambiguous expression boundary still need escaping; manual breaks/paragraph boundaries remain distinct from automatic Word wrapping.

Development mode, including the Playground, now explains syntax failures with a fixed reason, bounded expression excerpt, error position and available DOCX part/paragraph context. Curl receives the same development JSON and correlated container logs include `TEMPLATE_SYNTAX_DETAIL`. Production omits expression excerpts. Known secret-field expressions are redacted; other template literals may contain sensitive business text. Use synthetic development data.

The additive diagnostic context uses contract 0.5 while retaining original constructors and compatible earlier extension minima. DOCX/PDF providers declare the new minimum so older runtimes reject them before initialization. The website adds a date/time pattern reference and separate tested Maven/Gradle Java 17 starters for `prefix`, `uppercase` and `select`. These changes address #144.

The native PDF engine and passive attached-template policy retain their qualified profile. Standard PDF and PDF/A-1b, 2b and 3b remain supported; requested watermarks work in standard PDF, 2b and 3b, while 1b explicitly rejects them. Unsupported document constructs continue to reject. Java 17 remains the library/validator baseline and Java 25 runs the service/Playground. This is not universal Word compatibility.
