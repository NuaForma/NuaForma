# Dependency baseline

## Stable release and exception policy

The maintainer approved the [stable-component and upgrade-debt policy](ARCHITECTURE.md#stable-components-and-upgrade-debt) on 2026-10-22. Prefer the latest suitable stable component releases and current security patches, with official release-note/license review, exact pins and real compatibility/fidelity checks. This applies to tooling, transitives and bundled native/JVM inputs, not only direct Gradle libraries. Never use dynamic `latest` resolution in reproducible builds or infer that a newer release is safe without testing.

Intentional supported boundaries include Java 17 embedded libraries/extensions and the separately qualified Java 17 validators, alongside Java 25 server/Playground. Keep those boundaries while updating their appropriate patch lines; a baseline exception does not automatically approve an outdated patch. Existing Kotlin/Gradle and vendor validator-transitive constraints remain subject to the evidence below and must be reassessed before each release.

For an older-version exception, record the selected and newer versions, the tested/reproduced blocker or compatibility requirement, security impact, affected scope and a tracked owner/issue plus reassessment/removal condition. Do not silently carry an exception forward. Do not accumulate local forks, duplicate compatibility logic, unchecked overrides or weakened gates to make an upgrade appear complete. Any unavoidable workaround needs explicit approval, a bounded design, regression tests and a removal condition.

Release `0.2.0-alpha.2` is on hold for the approved Java security patch review. On 2026-10-22 Temurin 25.0.5+8 was announced; the official release's ARM64 JRE and matching multi-platform container input were not yet available when checked. The candidate still contains the previous pinned runtimes and is not advertised as upgraded. Do not mix architecture patch levels or bypass source/native qualification. Track completion in [release issue #105](https://github.com/NuaForma/NuaForma/issues/105); preserve older prepared source material as historical evidence and regenerate changed Java/provenance/approval records only after the new exact inputs are known.
