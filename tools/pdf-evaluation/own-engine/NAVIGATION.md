# Links, bookmarks and named destinations

Part 11 qualification for the shared native engine and production DOCX reader. Parent issue: #57. This is source qualification, not a published-release claim.

`PdfTextNavigation` carries inert link targets and immutable `PdfDestination` values separately from text styling. External targets accept only absolute HTTP, HTTPS and mailto URIs, without credentials, whitespace or control characters. Neither conversion nor validation fetches the target. Internal links must resolve to a unique document-wide destination. Caller-supplied destination titles create flat PDF outline entries. Navigation is collected from final physical text placements after wrapping, table positioning and pagination; hyperlink rectangles do not change text measurements or page geometry.

PDF URI actions use ASCII serialization with UTF-8 percent encoding for international paths. The caller's original target remains available in the neutral model, and the encoded form retains the same URI-size budget.

The DOCX adapter maps explicit `w:hyperlink` elements and matched `w:bookmarkStart`/`w:bookmarkEnd` ranges. A bookmark starts at the first following visible run in its paragraph. User bookmark names also become flat outline titles; underscore-prefixed internal names remain named destinations without cluttering the outline. Explicit run colors, fonts and single underlining are retained. Underline geometry uses the supplied font's own TrueType metrics. Duplicate/missing targets, unmatched markers and malformed or unsafe links reject explicitly.

The deterministic `build_navigation_fixtures.py` inputs cover A4 and US Letter, wrapped external links, mailto links, forward/backward internal navigation, a link inside a table and a longer report spanning several pages. `:nuaforma-docx-pdf:renderOwnEngineNavigation` renders them without a manual font/source staging step. The adapter tests exercise the registered provider and independent exact-byte validation for standard PDF and PDF/A-1b, 2b and 3b. Neutral tests inspect actual annotation actions, flags, rectangles, name-tree targets and outline entries, resource bounds, malformed inputs, immutable caller state and a shared engine under concurrent requests. An image-comparison test verifies that navigation changes no visible pixels, extracted content or pagination; existing reviewed golden files remain unchanged. Underline placement follows the [OpenType post specification](https://learn.microsoft.com/en-us/typography/opentype/spec/post): the supplied coordinate denotes the top edge, rather than the PostScript center coordinate.

Four genuine Microsoft Word exports cover nine page pairs: A4 (2), US Letter (2), a table (2) and a multi-page report (3). Every page retains normalized text, word order, wrapping and pagination. Maximum word-start/end/top differences are 0.192/0.190/0.128 points. All full-page comparisons and final content crops were visually inspected; link colors and underlines remain aligned. Original source/Word hashes, final candidate PDFs and per-page metrics remain with the local comparison evidence; Word and engine input part contents were checked for equality. No reference PDF or existing golden image was replaced and no mask/content-difference allowance was used.

The local full build/publication checks pass 812 JVM tests and all five independent Java/Kotlin consumers. The final URI-encoding increment then passes all 28 affected navigation, source-profile and golden-image tests, including the new ninth neutral navigation test. The registered-provider matrix includes 16 outputs / 36 pages across all four profiles; all 12 archival outputs use genuine independent conformance validation. The new engine-only navigation page is reviewed with PDFBox and Poppler, extending the inventory to 14 fixtures / 20 pages while leaving all 19 prior PNGs and input inventories byte-identical. Final-head complete CI and integration-branch analysis are linked through the delivery PR.

The bounded profile rejects navigation in text frames, bidi paragraphs, linked tabs/pictures, complex HYPERLINK fields, nested hyperlink content and bookmark starts with no following visible paragraph text. Only single run underlining is qualified; alternate underline styles/colors and unresolved theme formatting reject. Source hyperlinks need exactly one target, and external relationship targets must use the hyperlink relationship type. No remote images, active PDF actions, scripts, embedded files or new dependency are enabled. Heading-based hierarchical outlines, TOCs and computed references remain part 12. General Unicode bookmark names, arbitrary source field grammars and accessibility tagging remain outside this increment.

Budgets allow at most 2,000 navigation-bearing runs, 1,000 unique named destinations, 32 destinations on one run and 4,000 placed link fragments per PDF. Underlines must remain inside the supplied font's qualified bounds; underlining tabs or pictures rejects explicitly.
