# Footnotes and endnotes

Issue [#57](https://github.com/NuaForma/NuaForma/issues/57), roadmap part 13. The complete local build/publication checks pass 849 JVM tests with zero failures/errors/skips, plus five independent Java/Kotlin consumers. A focused preflight covers 97.1% of changed executable production lines; remote checks and the actual Sonar Quality Gate remain authoritative for delivery at the exact source/merge revisions. Integration delivery is recorded in the feature pull request. No release, output profile or new dependency is introduced.

## Model and layout

The shared `nuaforma-pdf` artifact owns immutable `PdfNote` definitions, typed owning `PdfNoteCall` occurrences, definition-local `PdfNoteLabel` markers and physical separator geometry. Source adapters resolve numbering in source order; pagination never increments a counter. Definitions retain logical note/reference/label identities, ordinary reference fields can cite their label targets, and generated PDF links work in both directions. This prepares future semantic output; it does not implement tagged PDF or PDF/A level A.

Footnote pagination reserves a page-bottom area transactionally before accepting the owning body lines. Rejected placements do not consume a note. Continuations preserve line order, paragraph spacing/keeps and labels without duplication; the continuation rule spans the text area. Endnotes follow the main text, with a separate rule and continuation pages. Body text, actual fonts, tables, existing page bands and final page-count iteration reuse the existing layout machinery. All mutable reservation state belongs to the current conversion.

`PdfTextStyle.baselineShift` expresses physical glyph rise independently of the source format. The DOCX adapter resolves its qualified superscript typography before layout. Automatic spacing preserves the ordinary natural font box and expands it when a raised marker requires more room; existing documents without raised markers retain their previous geometry. A future ODT adapter can supply its own effective sizes, shifts, numbering and note policies without adding ODT-specific logic to PDF rendering.

## Qualified bounded source scope

- Ordinary DOCX footnote/endnote parts and relationships, independently numbered continuous decimal, Roman or alphabetic labels, explicit starts and source IDs independent of display numbers.
- Page-bottom footnotes and document-end endnotes in one paginated section. Inert source bookmarks/links retain the existing resource policy; note calls in page bands, frames or notes reject explicitly.
- Paragraph text, inherited character/paragraph formatting, raised markers, explicit paragraph spacing, hanging indents, keeps/widows and qualified automatic line spacing. Notes cannot contain images, tables, nested notes, executable/general fields or a generated contents list.
- Atomic table rows with owning calls and repeated headers reuse existing table geometry; owning calls in repeated headers and row fragmentation with notes reject. Nested/vertically spanning tables with notes require a complete current-page placement. General wrapped-image/frame interaction with notes is outside this increment.
- Custom marks, each-page/each-section note-number restarts, section-end/beneath-text placement, visible continuation notices and custom separator styling/spacing reject rather than disappear. The qualified separator is a 12-point paragraph with a 144-point rule; continuation width is the full text area.
- Existing document/page/output limits and cooperative cancellation apply; additional bounds include 500 used notes, 128 paragraphs per definition and 20,000 measured footnote lines. No additional renderer process is introduced.

## Verification and independent Word evidence

`build_notes_fixtures.py` generates deterministic synthetic A4, US Letter, multipage, long-footnote, long-endnote, automatic-spacing and atomic-table cases. The production DOCX reader supplies the neutral model; no separate test reader implements notes. `OwnEngineNotesTest` checks source numbers, actual PDF content, page counts, all long-note sentinels, named targets, backlinks and embedded fonts. The registered provider runs all cases through standard PDF and PDF/A-1b, 2b and 3b, with independent validation of the actual returned bytes. Model tests also exercise concurrent renders, keeps, repeated headers, invalid placements, impossible protected groups, page budgets and cancellation.

Genuine Word exports are created read-only from these synthetic sources with `export_word.ps1`; Word never saves changes back to the source. Sources, Word PDFs, export receipts, generated PDFs and page comparisons are retained separately as review evidence. Word PDF font-size quantization and glyph positioning are recorded separately from actual source formatting differences.

Generate the seven source cases and ordinary PDF comparison candidates with `./gradlew :nuaforma-docx-pdf:renderOwnEngineNotes`. Copy the source/candidate files to a fresh evidence directory before creating Word exports. Run the existing `compare.py` with `--word-bounds` for each pair; only `split-note` uses the explicit `--allow-content-differences` switch, followed by the stricter complete-note/body audit. Run `python3 tools/pdf-evaluation/own-engine/audit_notes.py <reference-root> <engine-root> <comparison-root> <fresh-output.json>`, where comparison directories are named `notes-compare-<case>`. The audit refuses stale PDF hashes and an existing output file. PDFs produced by this comparison task alone make no archival claim; the registered-provider test performs independent PDF/A qualification.

All seven genuine Word proofs agree in page count (eleven page pairs). A4, Letter, the ordinary multipage report, long endnote, automatic-spacing document and atomic table have the same normalized content and words on every page. Their maximum observed line-baseline difference is 1.152 points (about 0.41 mm; the automatic-spacing case); the exact-spacing cases stay within 0.78 points. The long-footnote proof has a known continuation-boundary difference: the engine places one additional 12-point line on the first page. The same line continues on the second page in Word. Neither version loses text or changes its style. `audit_notes.py` verifies the complete ordered note stream, every unique long-note sentinel, unchanged owning-body pagination, geometry, clipping and exact current evidence hashes. This remains an explicit fidelity limitation, not a claim of identical pagination. The table fixture explicitly disables cell paragraph widow control, as required by the existing qualified table profile.

Engine-only goldens add `document-notes` (one page) and `continued-footnote` (three pages), covering raised markers, both note kinds, bands, continuation rules and a note-only final page. All four new PDFBox and independent Poppler pages were visually inspected. The previous 22 PNGs, inventory prefix and font/logo inventory are byte-identical. These new files supplement independent Word comparisons and cannot be regenerated during normal tests.

The Playground uses the same public provider automatically; no new UI is required. Release artifacts remain unchanged until separately authorized.
