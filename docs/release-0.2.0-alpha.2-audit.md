# 0.2.0-alpha.2 distribution review

This evaluation prerelease keeps five Java-17-compatible libraries, a Java 25 production service and a separate development Playground. Production and Playground each require native AMD64/ARM64 qualification and a distinct reviewed OCI index. Prereleases do not publish `latest`; previous tags and artifacts stay immutable.

## Explicit evaluation-alpha dispositions

On 2026-10-22 the maintainer freshly accepted the described remaining font/XML and additional librtmp native-runtime risks for **0.2.0-alpha.2**, conditional on final inventories confirming the reviewed pinned components without unexpected findings. The four candidate inventories satisfy that unchanged-input condition. This is not inherited alpha.1 approval, remediation or a production-safety claim. [Issue #51](https://github.com/NuaForma/NuaForma/issues/51) remains open.

The refreshed coordinate review queried 174 Debian/Maven coordinates and returned 192 distinct Debian advisory identifiers across 37 source-package matches. These are not 192 demonstrated exploitable NuaForma vulnerabilities. No Maven finding was returned for this coordinate set; the query does not cover every embedded component, unknown issue or reachable code path. Differences from the previous scan include changed coordinate coverage and must not be presented as an unqualified vulnerability-count trend.

[CVE-2026-112060](https://security-tracker.debian.org/tracker/CVE-2026-112060) and [CVE-2026-112061](https://security-tracker.debian.org/tracker/CVE-2026-112061) concern malicious RTMP server decoding in librtmp. Denied renderer networking limits that described path but is not a universal non-reachability proof. [CVE-2026-55467](https://security-tracker.debian.org/tracker/CVE-2026-55467) concerns CUPS scheduler/fax handling; the reviewed runtime contains libcups, not the scheduler daemon. That distinction does not dismiss every advisory for CUPS source. Historical FreeType/Expat findings remain unresolved. Namespaces, denied networking and processing limits mitigate exposure without repairing libraries or proving non-exploitability.

The maintainer also explicitly approved an exception to waiting for complete newer Java patch inputs, documented in [PR #109](https://github.com/NuaForma/NuaForma/pull/109) and the [runtime guide](java-runtime-compatibility.md). Both application architectures retain Temurin 25.0.4.1+1; sandboxed validators retain 17.0.20.1+1. [Temurin 25.0.5+8](https://github.com/adoptium/temurin25-binaries/releases/tag/jdk-25.0.5%2B8) is newer, but the matching ARM64 JRE/official multi-platform image were not available at the review. No vendor or packaging fork was introduced. Newer fixes are not claimed to be included, nor is the older runtime claimed vulnerability-free. Reassess this exception before the next release/runtime change; it does not carry forward automatically. The build toolchain's patch level is not proof of newer container runtime qualification.

## Qualification and distribution boundaries

The release adds development rejection explanations, mounted-font recovery, optional embedding of supported used fonts, bounded PDF parallelism, and the default-on operator conformance policy. Only exact `NUAFORMA_PDFA_VALIDATION=false` skips per-document veraPDF conformance validation; mandatory PDFBox validation, profile restrictions, isolation and limits remain. Disabled conformance validation must not be advertised as verified PDF/A. The Playground exposes the effective policy without a request-level override and remains development-only with conspicuous warnings and potentially sensitive logging.

The actual native candidates passed their configured enforcing isolation probes, shipped endpoint/health/SBOM checks and official CycloneDX schema validation. Both production variants additionally passed the service/profile/cancellation/cleanup checks. Existing renderer/layout/barcode evidence stays scoped to its recorded fixtures and supported template profile. The accepted text-box placement limitation in [issue #32](https://github.com/NuaForma/NuaForma/issues/32) remains unchanged. At the maintainer's request, no extra local document generation, rendering or container qualification is performed during this publication; required native release checks are not waived. Small historical throughput trials are not new alpha.2 benchmarks or sustained/hourly guarantees. The disposable ODT/FOP experiment is not release functionality.

Protected archive and publication workflows must verify the reviewed records rather than infer approval from successful tests. Registry publication consumes the final reviewed archives, without rebuilding, overwriting tags or adding `latest`. Match `VALIDATED` before requesting Central publication; if the maintainer publishes directly, inspect the outcome rather than requesting publication twice.

The separate website must update versions, both OCI index digests, immutable runtime profiles, documentation and all nine existing kits after public artifact availability. Verify Pages HTTPS and every live ZIP checksum before closing [release issue #105](https://github.com/NuaForma/NuaForma/issues/105). That later final-archive, public-artifact and site evidence remains separate from this completed candidate-source review.
