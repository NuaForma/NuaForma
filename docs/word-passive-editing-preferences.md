# Passive picture and revision-recording preferences

Unreleased source qualification under [#249](https://github.com/NuaForma/NuaForma/issues/249).

The native PDF path validates `doNotAutoCompressPictures` and `trackRevisions` as passive editing preferences and omits them only from its private print interpretation. Standard boolean spellings and the omitted-value default are supported. Original namespaces, leaf shape and uniqueness are checked before DOCX serialization, alongside the already supported editor toggles. Invalid original metadata receives a source part, construct and development explanation.

Microsoft defines [automatic picture compression](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.donotautocompresspictures?view=openxml-3.0.1) as a preference for saving document images, and [revision recording](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.trackrevisions?view=openxml-3.0.1) as recording changes to the document. Neither preference alone adds visible content. NuaForma does not introduce image recompression, record new revision markup, or accept/delete existing revisions as part of this qualification.

Actual insertions, deletions, moves and formatting-change structures retain their separate profile restrictions. Regression inputs with insertions, deletions or formatting changes reject without partial PDF whether the recording preference is on or off. This work does not add a tracked-change view or revision-processing feature.

Qualified cleanup returns the original template bytes, including these preferences. Normal DOCX-to-DOCX behavior is unchanged. The Playground shares the provider's qualification and focused development diagnostics; there is no separate permissive rendering path or UI change.

The A4/Letter probes differ from existing package controls only in `word/settings.xml`; all other part bytes remain exact. Their two new Word-export page rasters are identical to the existing Word references. All eight validated PDF/profile pages must match the existing golden images exactly at 96 dpi, with unchanged text, geometry and embedded fonts. No new golden image or replacement is required.

Rebuild the synthetic sources using `python tools/pdf-evaluation/own-engine/build_editing_preferences_fixture.py --base nuaforma-docx-pdf/src/test/resources --output build/editing-preference-sources`. Run `./gradlew :nuaforma-docx-pdf:test --tests 'dev.nuaforma.docx.pdf.NativeEditingPreferencesTest'` and the normal full build. Reference files are never regenerated by tests.

## Unused document-variable storage (source #251)

Qualified `w:docVars` storage remains in the original template and is omitted only from the request-local print model. It cannot activate template instructions, select fonts or change text direction, even when names or values contain braces or non-Latin text. This source qualification does not add `DOCVARIABLE` field evaluation; such displayed fields still reject without a partial PDF.

A single correctly namespaced container may hold up to 1,000 leaf name/value entries. Names are nonblank, at most 255 characters and unique after locale-independent lowercasing; each required value may be empty and is at most 16,384 characters. The aggregate name/value size is limited to 65,536 characters. Invalid containers, namespaces, attributes, leaves, missing values, ambiguous names and excess sizes reject. Original storage is validated before DOCX serialization can discard malformed properties, with a focused development part and XML path. Existing input/XML budgets and cancellation continue to apply.

Two A4/Letter fixtures under `document-variable-storage` add only stored values to the existing package controls. They contain unfinished template-looking strings, XML punctuation, empty values and Cyrillic/Arabic/Chinese text. Independent Word exports must remain pixel-identical to existing references. All four PDF profiles reuse existing immutable images; tests verify source/cleanup bytes, original-source errors, bounded storage, rejected displayed fields and concurrent tenants.

Rebuild using `python tools/pdf-evaluation/own-engine/build_document_variables_fixture.py --base nuaforma-docx-pdf/src/test/resources --output build/document-variable-sources`, then export independently with Word and the exact fixture fonts. Run `./gradlew :nuaforma-docx-pdf:test --tests 'dev.nuaforma.docx.pdf.NativeDocumentVariablesTest'` and the normal build. The Playground shares the same admission and diagnostics; no UI option or production fallback is introduced.

Microsoft describes [document-variable storage](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.documentvariables?view=openxml-3.0.1) separately from [the fields needed to display it](https://learn.microsoft.com/en-us/office/vba/api/word.variables.add). This bounded qualification covers unused storage.
