# Tabs after template data expansion

This source change follows Word when right, center or decimal alignment would move a tab's following text behind the current text position. The field starts at the current position instead. A collision does not insert an artificial space, move the preceding text or change font measurements. A fraction-of-a-point collision receives the same treatment as a larger collision.

The selected stop is still the first custom stop beyond the current cursor. After the final custom stop, the next automatic left stop is selected from the configured interval. A longer substituted value can therefore select a later stop. There is no public API, package, dependency or request-schema change; the shared PDF engine resolves the layout, and DOCX supplies its existing typed stops. A future ODT adapter can use the same neutral settings.

Microsoft documents [tab advancement](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.tabchar#remarks), [automatic intervals](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.defaulttabstop#remarks) and [alignment anchors](https://support.microsoft.com/en-us/word/using-the-ruler-in-word). Collision placement was established independently with actual Microsoft Word exports, rather than inferred from those definitions alone.

## Tabs near the right margin

For right, center and decimal stops beyond the text area, Word aligns the following field at the paragraph's right edge. An explicit right stop inside the text area can still be reached when a positive paragraph indent puts it beyond the normal line edge. The extra room applies only to that line; the containing area still bounds placement and preceding text keeps its position. Left stops beyond the available area are outside this qualification.

## Qualification

`python3 tools/pdf-evaluation/create_tab_collision_fixtures.py <fresh-directory>` builds A4/Letter templates and independent short, colliding and passed-stop controls. It refuses an existing output directory and writes no reference PDFs or golden images. Each template uses a real `{prefix}` expression before twenty tab fields. The controls cover left/right/center/decimal stops, all four supported leaders, subsequent custom and default stops, and three hanging-indent fields. The Word reference authoring procedure disables macros and external link updates and preserves the exact input bytes.

The provider regression substitutes each value through normal template evaluation and compares all 43 content anchors per output with the matching Word export, within 0.21 point. It exercises standard PDF and representative PDF/A-1b/2b/3b requests, embedded fonts, page counts and independently reviewed initial native golden images. Full text comparison normalizes whitespace and only the decorative leaders between the fixture's prefix/value markers: their glyph counts can differ from Word. Native golden images assert every pixel at 96 dpi with no masks. Shared-engine tests reproduce the reported `-36.0` versus `-36.12` collision using deterministic font metrics and check passed stops and zero-width gaps. Existing golden images are preserved.

The synthetic margin controls in `nuaforma-docx-pdf/src/test/resources/tab-margin` use the parts generated by `tools/pdf-evaluation/create_tab_collision_fixtures.py` with an empty prefix. Their main document contains a left-aligned paragraph with `P00_PREFIX`, a tab and `123,T00`, followed by `P99_NEXT` in a second paragraph. The section has 1,134-twip side margins on A4 or Letter. The `right` variant puts the stop 420 twips beyond the text area and sets a 260-twip right indent. The `indent-only` variant places the stop 100 twips inside the text area, with a 400-twip right indent. Both use Word compatibility mode 15 and the base fixture's Liberation Sans and exact line height. Each export has a receipt for the exact evaluated input. Maintained provider tests compare all three anchor positions with Word on each paper size; shared tests also cover center and decimal fallback, a stop at the text-area boundary and rejection when preceding text leaves too little space.

The source change does not relax physical page, line, table-cell or resource bounds. Content that still exceeds the qualified area after collision placement remains an explicit measured rejection. General right/center/decimal reflow at the end of a line and tabs on non-final justified lines are not newly qualified by these controls. The Playground and production service use the same provider; no separate UI change is required. This work is not present in unchanged `0.5.0-alpha.4` artifacts.
