# 0.3.0-alpha.1 distribution review

This evaluation alpha replaces LibreOffice with the shared native PDF engine. Six libraries remain Java 17 compatible; the production service and separate development Playground use Java 25 with independently bounded Java 17 validators. Production and Playground each require a distinct native AMD64/ARM64 index. Prereleases do not move `latest`; older artifacts remain immutable.

## Fresh security and patch disposition

On **2026-10-26**, the maintainer explicitly accepted retaining the qualified official Java images and the described remaining font/XML and other runtime findings for **this evaluation alpha**, with remediation tracked under [#51](https://github.com/NuaForma/NuaForma/issues/51), milestone 0.4.0. This is fresh release-specific acceptance, not inherited approval from 0.2.0, remediation or a production-safety guarantee. Final inventories must contain the reviewed inputs without unassessed changes.

The refreshed OSV coordinate review queried 141 Debian/Maven coordinates and returned 82 advisory identifiers across 22 Debian source-package matches. These are not 82 demonstrated reachable NuaForma vulnerabilities. No indexed Maven match was returned for these coordinates. The retained review maps findings to actual installed binary packages; source-package matches, absent daemons and processing limits do not alone prove non-applicability. JVM/vendor, embedded-component and unknown-issue coverage remains a separate consideration. Removing LibreOffice and changing the coordinate set must not be described as an unqualified vulnerability-count improvement.

The fresh patch review checked official Adoptium binary releases and Docker Official Images definitions. [Temurin 17.0.21+9](https://github.com/adoptium/temurin17-binaries/releases/tag/jdk-17.0.21%2B9) and [25.0.5+8](https://github.com/adoptium/temurin25-binaries/releases/tag/jdk-25.0.5%2B8) have Linux AMD64/ARM64 JRE binaries, but the [official image definitions](https://github.com/docker-library/official-images/blob/master/library/eclipse-temurin) still select 17.0.20.1+1 and 25.0.4.1+1 at recipe `511f9356dc4d50932a0a5f8cfb0f87ed1aef4f07`. The corresponding newer Noble JRE image tags were unavailable during review. No vendor/packaging fork is introduced. The maintainer explicitly accepted this patch exception again for 0.3.0-alpha.1; newer security fixes are not claimed incorporated. Reassess availability and exact source/runtime qualification before the next release; this exception does not carry forward automatically.

## Fidelity and release boundaries

The complete native source build passes 869 JVM tests without failures/errors/skips and five independent Java/Kotlin consumers; 21 container-tool and 39 release-tool tests pass. Existing protected golden files are unchanged; watermarks add four reviewed initial pages. Seven versioned HTTP examples pass independent output/profile checks and were compared with genuine Word exports: 12 page pairs and 6,547 body characters agree in content/order, font faces and pagination, with maximum text differences of 0.265 pt horizontally and 0.220 pt vertically. Every paired page was visually reviewed; source/export provenance and checksum-bound evidence are retained. This is an explicitly authored bounded profile, not arbitrary Word compatibility. WordArt/native watermark contour differences remain documented.

Both real packaged clients passed 12 requests each, including all seven document scenarios, against the native candidate. The qualification helper derives the expected request count from the packaged scenario manifest instead of retaining its older six-scenario count. Final released-image/site verification remains part of publication handoff.

Standard PDF, PDF/A-2b and PDF/A-3b accept requested text watermarks. PDF/A-1b explicitly refuses every requested watermark, including opaque or empty-resolving requests. Unsupported source structures/scripts fail explicitly. PDF/A level A/UA, ODT, RTF and broader import coverage are outside this alpha. Bibliography/custom-XML follow-up #54 also remains in milestone 0.4.0.

The final native variants must pass actual service/profile, endpoint/health/SBOM, cancellation, cleanup and default-container-boundary checks. No custom host seccomp/AppArmor profile, Bubblewrap, privileged/unconfined execution or production Playground UI is introduced. The engine renders in-process; validators remain separate bounded processes. Default container policies do not establish network denial or remove component vulnerabilities.

Publishers consume the exact reviewed archives instead of rebuilding or overwriting immutable tags. Central upload is USER_MANAGED; require VALIDATED and exact artifact hashes before the separately authorized publication. Inspect uncertain outcomes rather than blindly retrying. The website remains a separate checked promotion: bind the actual public production/Playground digests, preserve historical performance baselines, verify the seven scenarios/client kits and check live downloads after deployment. This document does not substitute for those final checks or their explicit approval records.
