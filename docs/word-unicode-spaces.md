# Unicode spaces at text-run boundaries

Unreleased source qualification under [#252](https://github.com/NuaForma/NuaForma/issues/252).

The DOCX reader distinguishes XML S whitespace (ordinary space, tab, CR and LF) from Unicode spacing characters. Nonbreaking space U+00A0, figure space U+2007 and narrow nonbreaking space U+202F remain document text when `xml:space="preserve"` is omitted or the default is selected. Existing glyph, shaping, font and resource policies still apply. This does not qualify every Unicode spacing character or silently trim unmarked ordinary XML edge whitespace.

The neutral PDF model retains the original Unicode text. Qualified spacing and nonbreaking behavior pass through the existing PDF engine without a public model change, new dependency, alternate renderer or font substitution. An unsupported source remains an error with no partial PDF. Template-expression evaluation and other DOCX round-trip behavior are unchanged. The Playground uses this same reader and its source diagnostics; accepted cleanup retains the original template bytes.

The A4/Letter fixtures cover leading/trailing and space-only runs for all three characters, ordinary preserved-space controls, real bold/regular fixture fonts, colors and a 180-point wrapping comparison between a nonbreaking pair and an ordinary-space pair. Both source variants have independently exported Word references: the explicit-preservation control and implicit target produce identical Word pixels. Forty measured markers retain their page, physical face, color and point size; maximum position differences against the control-engine output are 0.164 pt horizontally and 0.124 pt vertically. Per-line extracted text matches Word after spacing-character normalization.

Two initially reviewed engine images are new immutable goldens; no existing golden is replaced. They come from the already accepted explicit-preservation control. All eight control profile pages match those images exactly at 96 dpi without masks and embed their used fonts. Regression tests require the implicit source to retain the same model text, source/cleanup bytes, Word line breaks and golden pages across standard PDF and PDF/A-1b, 2b and 3b. PDF extraction may normalize spacing glyphs; model-level assertions independently check the original characters.

Rebuild using `python tools/pdf-evaluation/own-engine/build_unicode_space_fixture.py --base nuaforma-docx-pdf/src/test/resources --output build/unicode-space-sources`. It produces `preserve/{a4,letter}` controls and `implicit/{a4,letter}` targets without overwriting an existing directory. Export all variants independently using the exact fixture fonts; reference generation is never part of the tests. Run `./gradlew :nuaforma-docx-pdf:test --tests 'dev.nuaforma.docx.pdf.NativeUnicodeSpacesTest'` and the normal full build.

The distinction follows [XML whitespace handling and its S production](https://www.w3.org/TR/xml/#sec-white-space) and [WordprocessingML space preservation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.texttype.space?view=openxml-3.0.1). The references describe the formats; the probes above define the qualified subset.
