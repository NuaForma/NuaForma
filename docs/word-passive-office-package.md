# Passive Office package resources (source #233)

This unreleased source profile admits bounded, validated resources without treating them as printed text or template instructions. It does not add custom-XML binding, external resource retrieval, source-font substitution or arbitrary DrawingML effects.

- A single empty `mso-contentType` processing instruction before the root of `customXml/itemN.xml` is accepted. Other instructions, nonempty arguments, duplicate instructions, instructions inside/after the root, DTDs and entities remain errors. Generic XML parsing remains strict; malformed conversion-copy diagnostics identify the offending part.
- Internally owned Office content-type schemas, document-management properties and SharePoint form-template metadata are excluded from the private print model. Their namespace/root pairs, relationships and optional datastore properties are checked first. Schemas and forms are never executed or fetched. Unknown custom XML continues through the existing strict bibliography admission; active Word data bindings reject explicitly.
- `word/stylesWithEffects.xml` requires its matching relationship/content type and equivalent supported ordinary styles/defaults. XML prefix, property order and equivalent on/off spelling do not create false differences. Additional ordinary styles must be unused and nondefault. Active or divergent formatting remains unsupported. Cleanup of that failure removes the auxiliary part rather than ordinary styles or story text.
- Empty or internally owned font-table relationships and bounded `.ttf`/`.odttf` resources are accepted after graph/identity checks. Source font declarations are excluded from the private print model; font bytes are not decoded or installed. The caller must still supply every used face through the existing font catalogue. Missing fonts remain an error.
- Internal PNG/JPEG theme-image relationships are accepted when complete and unused by printed theme-style references. Missing, external, orphaned and ambiguous resources remain errors. Active theme-style use with these images is not qualified.

The original package is retained by the owning DOCX serializer. Admission changes only the reader's request-local print model. Existing archive/XML limits, deadlines, cancellation and output validation remain unchanged. No public API, dependency or request option is added.

## Playground and regression coverage

The Playground uses the same provider. Qualified packages need no cleanup changes; unsupported active resources still produce source diagnostics and focused cleanup. Metadata containing braces does not activate template evaluation. There is no permissive fallback or automatic font replacement.

Two synthetic A4/Letter fixtures combine all admitted graphs, with nonprinting unclosed-brace metadata, embedded Liberation Sans, an unused theme image and equivalent auxiliary styles. Real Microsoft Word exports are committed with source/PDF hash provenance. All four PDF profiles must match the existing typography golden images exactly, retain Word text positions and embed caller fonts. Tests also cover malformed graphs, divergent styles, no network retrieval, missing caller fonts, cancellation and cleanup retaining story/style bytes. Existing bibliography rejection tests remain applicable.

Fixtures live under `nuaforma-docx-pdf/src/test/resources/passive-office-package`. The utility `tools/pdf-evaluation/own-engine/build_passive_office_fixture.py` takes `--base`, `--theme-source`, `--font` and a fresh `--output`; it refuses to replace a fixture. The A4 base is `typography-preferences/trailing-1/source.docx`; Letter uses `typography-preferences/bands-letter/source.docx`. The theme comes from the own-engine styles fixture and the font from the approved Liberation Sans test resources. Export each new source with `export_word.ps1 -Source ... -Output ... -UpdateFields`. Existing golden files are immutable; these cases reuse the corresponding base images.

The scope follows Microsoft's descriptions of [styles parts](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-extract-styles-from-a-word-processing-document) and [document-property custom XML](https://learn.microsoft.com/en-us/previous-versions/office/developer/sharepoint-2010/bb447589%28v%3Doffice.14%29). These references describe the formats; the restrictions above define NuaForma's qualified subset.
