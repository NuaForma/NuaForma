# Marked template diagnostic PDF

This development-only operation locates a parser error in a private template, starting with the selected `0.3.0-alpha.4` release (#150). Consult the actual signed release for public availability; published alpha.3 does not include it. Normal generation still fails; the diagnostic PDF is a separate artifact, not a generated business document or archival export.

After a syntax failure, choose **Download diagnostic PDF** in the Playground. The browser resends the original failed request, template and resources, even after builder edits. A request-private copy preserves literal template content, adds a red `[ERROR 1]` marker and appends an explanation page with the reason, part, paragraph, local position and bounded excerpt/caret. Known secret-field excerpts remain redacted. The document itself contains original template text: protect development instances and downloaded files.

Only the first locatable error is marked. Mapping uses actual Word objects, not text search. Structural block errors mark the opening paragraph. Mixed object/text runs are colored with a label at the failed text position. Adding the label can change wrapping; this is a navigation aid. Automatic wrapping does not split expressions; manual breaks and Word objects can introduce separate fragments.

`POST /api/v1/diagnostics/template` accepts the ordinary bounded multipart request/template/resource parts. It exists only in trusted startup development mode; production returns 404 and requests cannot enable it. A successful diagnostic operation returns independently validated standard PDF with filename `template-diagnostic.pdf`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Request-ID` and `NuaForma-Diagnostic-Artifact: template-error`. The original output profile and requested watermark do not apply to this separate diagnostic artifact. Caller font declarations/resources still apply.

Contract 0.6 adds optional `TemplateDiagnosticProvider.diagnoseTemplate(request, output, context)`. Native PDF implements it with an explicit development-context requirement. Original provider interfaces/constructors remain unchanged; older runtimes reject new built-in providers before initialization. `DocxProvider.diagnosticCopy` prepares the marked DOCX. No new artifact or production dependency is introduced.

Package checks, native profile restrictions, font policy, admission, byte/work limits, cancellation and mandatory structural validation remain enabled. There is no Office fallback, external retrieval, second evaluator, server-side artifact cache or partial success output. Unsupported source layouts/fonts can prevent PDF creation. The Playground retains the original error and reports why the PDF is unavailable; it does not substitute a text-only PDF. Valid templates and errors without a reliable source mapping produce no diagnostic artifact.

Source fix #154 excludes Word hidden text from syntax activation and omits it from the private PDF intermediary. Only a visible parser error can create the diagnostic; a template with only hidden errors is valid for syntax inspection and does not produce a diagnostic PDF. See the DOCX visibility rules for inherited styles, overrides and unsupported conditional table visibility. This does not establish the cause or resolution of an unrelated DOCX serialization failure.

## Source diagnostics and DOCX inspection (alpha.6)

Current source adds development-only source details for native conversion rejections: `sourceExplanation`, `sourceConstruct`, `sourcePath` and a bounded, secret-aware `sourceExcerpt`. `part` identifies the logical DOCX part; `documentLocation` counts paragraphs from one within that part, including table cells. Indexed XML paths identify tables (`w:tbl`), rows (`w:tr`), cells (`w:tc`) and properties. XML line/column coordinates refer to the private serialized conversion copy, not Word pages or the original ZIP byte offset. Styles/settings can fail without a paragraph; the diagnostic reports their actual part/path rather than inventing a page or paragraph. Original Word page numbers cannot be established when layout fails. Block-level excerpts come from that rejected block, not an unrelated first paragraph. Legacy/unmapped checks still report their concrete application-owned rejection reason, but omit unavailable coordinates instead of inventing a source node.

The Playground offers **Download marked DOCX** after failed generation. `POST /api/v1/diagnostics/document` repeats the original failed request, retains the filled conversion copy when available and marks its first located paragraph with `[ERROR 1]`. It appends the reason and source coordinates. Syntax errors retain the original source. Unlike a diagnostic PDF, the DOCX inspection copy does not require successful native pagination, font embedding or PDF validation. Package validation, private files, limits and cancellation still apply: malformed/unsafe packages or serialization errors can also prevent DOCX inspection. This is an inspection artifact, not success or a PDF/A deliverable.

**Preview with error markers (DOCX)** calls the same endpoint with `?preview=true`. Source fix #177 keeps malformed contiguous text fragments literal and marks only the first locatable parser failure with `[ERROR 1]`, directly at its failing source position. The appended report identifies the concrete reason, logical part, paragraph and bounded parser fragment/position; other malformed fragments remain literal without duplicate generic error labels. Independently valid fragments are evaluated with the ordinary template session. Control detection uses printed text only; Word field instructions cannot activate preview blocks. It does not repair braces or pair them across Word objects, paragraphs or manual breaks. Structural `if`/`each` regions remain literal with `[LITERAL BLOCK]`, including both alternatives. A mismatched/orphan control makes the remaining container uncertain and literal; no branch is guessed. Valid inline structural regions are also preserved conservatively. Valid content pipes retain their ordinary placement rules and limits. Other evaluation failures (such as missing required data) remain errors. The document carries a conspicuous diagnostic-only label. Normal generation stays strict and publishes no partial output.

Both inspection modes return DOCX with `NuaForma-Diagnostic-Artifact: document-error`, `Cache-Control: no-store` and `nosniff`; routes are absent in production. The browser resends the captured failed upload, not subsequently edited builder state. Original diagnostics remain visible. Source excerpts and coordinates are exposed in development responses and development trace logging only; production retains restricted diagnostics. Copies contain private source/data, so protect development instances and downloaded documents.

Contract 0.8 adds `DocumentDiagnosticProvider.diagnoseDocument` and immutable `DocumentSourceContext`, attached using copy-returning `Diagnostic.withSourceContext`. Existing JVM constructors and the PDF-only facet remain compatible. Built-in DOCX/PDF providers require 0.8; older compatible provider minima remain accepted. The selected alpha.6 includes these additions. Earlier alpha.5 artifacts remain unchanged on contract 0.7.


### Passive Word markers (source fix #177)

Same-paragraph bookmarks, spelling/grammar proofing markers and cached page-break hints do not split printed template text. They remain zero-width metadata, not template input; hidden text, field instructions and document properties cannot activate expressions. Bookmark identities/order and source formatting are retained, with internal replacement boundaries collapsing to its start. Real breaks, tabs, fields, hidden runs, hyperlinks/containers and separate paragraphs remain boundaries. This correction does not establish the cause of a private document's failure without reproducing it. It is a source change after alpha.6; existing releases remain immutable.
