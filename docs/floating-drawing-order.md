# Floating drawing order

The development candidate adds optional immutable `drawingOrder` / `withDrawingOrder(order)` on `PdfTextBox` and `PdfAnchoredImage` in the existing shared PDF artifact. `PdfDrawingOrder(layer, stackingOrder, tieBreak)` separates background/foreground painting from body flow. Keys are bounded nonnegative 32-bit unsigned values; lower keys paint first, and equal keys retain input order. Null retains the previous model policy. Existing constructors, image components and copy signatures remain available; copies retain order. The extended anchored-image class no longer carries Kotlin's data-class marker. No dependency or artifact is added.

DOCX resolves `behindDoc`, `relativeHeight` and `docPr/@id` into physical layer, primary order and tie break. Genuine A4/Letter Word controls show that reversing XML object order does not reverse differing drawing orders; equal heights use the drawing identity. Raster pictures and text frames use the same painter. Normalization, references and page-band reconstruction must preserve these values. Source attributes are checked before typed binding, including Boolean values, integer bounds and qualified editing identifiers.

For page-relative, unwrapped body frames, valid `wp14:anchorId` / `editId`, locking and cell-layout editing flags do not alter the tested printed geometry. Controls retain these values independently rather than testing only one combined case. Wrapping distances reserve no text exclusion when wrapping is disabled. Original source geometry, picture effects, resource limits and cancellation remain independently enforced.

This work does not implement Word's automatic relocation with `allowOverlap=false` or `simplePos=true`, general frame reference areas, wrapped background pictures, overlapping floating raster pictures or overlapping page-band objects. Such combinations retain explicit rejection; order metadata is not permission to approximate their geometry. VML frame behavior is unchanged. The Playground uses the same adapter and renderer; no separate UI, remote resource lookup or fallback renderer is introduced.

`python3 tools/pdf-evaluation/create_floating_drawing_fixtures.py <fresh-directory>` creates inert A4/Letter sources, including foreground/background objects, differing/equal/reversed order, maximum order, editing flags and raster/frame intersections. Word exports retain original source hashes. Native images are initially authored only after independent Word comparison; established golden files stay protected. Candidate renderer qualification is recorded after those checks pass.

Targeted drawing-order qualification on 2026-11-18 passes 42 actual Word/native page pairs and protected initial native images, including all four PDF profiles on A4 and standard PDF on Letter. Actual Playground requests additionally pass 126 PDFs across the four profiles and precise original-source rejections. The unchanged local corpus retains 21 standard-PDF successes and all 59 preceding pages with exact text and pixels. A changed first diagnosis does not establish complete document support. Combined normal-build qualification remains separate.

## Inactive anchor metadata

The source adapter additionally validates false `hidden` flags, zero-valued `wp14:sizeRelH` / `sizeRelV` placeholders and inactive `wp:simplePos` coordinates for frames, pictures and DrawingML lines. These values remain separate from actual placement and size. Original attribute namespaces, duplicates, child structure and numeric values are checked before typed binding. Inactive coordinates stay bounded to ±14,400 points; they never allocate a canvas or replace the active position. True/invalid hidden flags, nonzero relative sizes and active simple positioning remain explicit source rejections.

`python3 tools/pdf-evaluation/create_floating_metadata_fixtures.py <fresh-directory>` builds 36 inert controls across the three object kinds and A4/Letter. Genuine Word exports prove exact pixels against each kind's control for individual settings and their combination. Native renderer qualification is recorded when its independent comparison and regression checks complete. No public-model API or resource limit is changed by these passive settings.

Targeted checks pass 36 native/Word page pairs and protected initial images, with 45 regression PDFs: every source in standard PDF, plus the combined case for each object kind in all four profiles on A4. Actual Playground qualification passes 78 PDFs, including every source in standard PDF/PDF-A-3b and the combined A4 cases in PDF/A-1b/2b. Four original-source negatives include the precise unsupported extent side. The unchanged local corpus retains its 21 successes and 59 pixel-identical pages; 29 first diagnoses change. Combined normal-build qualification also passes.

## Opaque preset frame paint

Page-relative rectangular DrawingML text frames accept the opaque `black` and `white` presets in their explicit fill and centered stroke, with the same paint as the corresponding RGB values. Other presets and transforms on presets still report the original color element.
